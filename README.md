# Acorn

A C++20/OpenGL learning project for an Engine course. Acorn currently contains procedural geometry, model-import comparisons, texture loading, and interactive rendering demonstrations.

Last updated: **2026-11-18**.

## Build and run

The project uses xmake, GLFW, GLM, GLAD, Assimp, and stb_image. It requests an OpenGL 4.6 core context, so the graphics driver must support that version.

From a complete project checkout, in the directory containing `xmake.lua`:

```powershell
xmake
xmake run Acorn
```

xmake manages its declared packages. The project also needs `stb_image.h` on its include path (the configuration includes `inc`) and the `shaders`, `textures`, and `models` directories. `src/stb_image.cpp` supplies the stb implementation but still needs the header.

Paths such as `shaders/basic.vert` and `shaders/basic.frag` are relative to the process working directory. For an IDE run, use the project root as the working directory. The build also copies asset directories beside the executable.

See [Windows and Rider setup](docs/windows-setup.md) for workstation setup, solution generation, and troubleshooting.

## Current functionality

- Procedural pyramids, cubes, and a sphere, with several vertex-layout/appearance examples.
- CPU mesh data, move-only GPU mesh/model owners with automatic cleanup, and model instances referencing shared uploads.
- Custom OBJ parsing and an Assimp import path, shown side by side.
- Texture loading, adjustable colour blending and texture tint, per-face colour draws, and optional directional lighting.
- Perspective/orthographic projection, an orbiting camera, and transform animations.
- Shader compilation/link diagnostics, OpenGL error logging, and development assertions.

The basic shaders use GLSL 4.60. The renderer explicitly selects lighting for each draw and uses mesh attribute availability to guard model lighting and texturing.

## Controls

| Key | Action |
| --- | --- |
| Escape | Close the application |
| Tab | Toggle wireframe |
| Caps Lock | Toggle face culling |
| Enter | Toggle perspective/orthographic projection |
| 0 | Toggle background colour |
| 1 | Default procedural shapes |
| 2 | Backpacks |
| 3 | Teapots |
| 4 | Imported cubes |
| 5 | Pines |
| 6 | Sports cars |
| 7 | Heads (`Ipshead` in the code) |
| 8 | All imported-model comparisons |
| Q / W / E | Toggle X / Y / Z scale animation |
| A / S / D | Toggle X / Y / Z rotation animation |
| Z / X / C | Toggle X / Y / Z translation animation |
| Space | Reset controlled transforms and disable their animation toggles |

Transform controls affect the active demonstration's controlled objects. The default-shapes scene also has independent automatic animations. Space does not reset those independent animations, the camera, or the scale/translation direction flags.

## Code and rules

| Location | Responsibility |
| --- | --- |
| `src/main.cpp` | Startup, input, texture loading, demonstrations, main loop, shutdown |
| `src/geometry` | CPU mesh representation and procedural shapes |
| `src/assets` | Importers and load/upload convenience functions |
| `src/rendering` | GPU resources, instances, drawing, shaders, diagnostics |
| `src/AcornMath.*` | Transform representation and model matrices |
| `src/Palette.h` | Named colours |
| `shaders/basic.vert` and `shaders/basic.frag` | Vertex transforms, colour/tint calculation, and lighting |


## Current limitations

- Instance pointers borrow resources and require owners to stay alive at stable addresses. Demo containers must not be moved while their instances refer to their members.
- Textures are shared through raw IDs and are not explicitly deleted during shutdown. GPU meshes/models have automatic cleanup; the shader program is deleted explicitly.
- The custom importer supports a subset of OBJ; unsupported/rejected faces may abort an import or be skipped, depending on its arguments.
- The Assimp adapter does not preserve node transforms, materials, or animation. Textures are selected by demo code.
- Missing normals are not generated by either importer. The basic sphere has no normals or UVs.
- Per-face colouring issues one draw per face range.
- No automated test target or model cache is configured. Models are shared through explicit references established by the demo code.
- The shader wrapper and uniform cache currently include assumptions specific to the basic shader.
